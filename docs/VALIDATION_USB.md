# 1.1.0 USB 功能验证

日期：2026-10-07。板卡：当前 ESP32-S3 N16R8、CH334F hub、原生 USB 与独立 CH340；原有约 1 GB SD 卡。主机：Linux，标准 usb-storage 驱动及 UDisks。

## 已执行

- 固件编译通过；14 组 C/C++ 测试使用 ASan/UBSan，另有 Python 构建/烧录脚本测试。新增 USB 边界、跨扇区保留数据、I/O 失败、60 秒计时及回绕测试。本机存储在 USB 占用时不会发起目录访问。
- 第二页菜单 USB 图标位于 Home Assistant 前；确认弹窗、取消、等待、连接、传输和弹出状态截图已保存。音乐播放时取消确认，播放与本机 SD 状态保持不变；确认开启停止播放并交接 SD。
- Linux 枚举得到 `GPT Voice SD` / `GPTVOICE SD CARD`，只包含原 SD 容量。电脑挂载后可以复制、中文重命名、创建及删除文件。
- 先备份原 SD 文件；在独立测试目录复制 4,194,304 字节二进制、1,444 字节 PNG 和 4,715,611 字节 MP3。复制、同步及第一次回读约 60.69 秒（当前板卡和 SD 组合，不代表最高性能）。安全弹出后重新连接，原文件和新文件 SHA-256 全部一致。
- 传输期间，本机音乐、语音和存储入口拒绝访问 SD。电脑尚未弹出时，“结束 USB 传输”不会强行重新挂载；烧录脚本也会拒绝复位操作。
- 使用 UDisks Drive.Eject 发送真实 SCSI 弹出，固件等待响应完成后恢复 SD，原生 USB Serial/JTAG 重新枚举。只卸载文件系统不会被误认为安全弹出完成。
- 通过串口维护命令保持 USB 软件断开，实机运行完整 60 秒计时及 SD 交接；约 60.14 秒恢复普通模式。另验证等待期间取消。此项模拟未连接主机，没有用独立充电器做物理拔插试验。
- 修复 SD 全局 deinit 会重置未使用槽位的 GPIO0 后，再次验证超时、取消、安全弹出与连续三次连接/弹出；BOOT 输入保持高电平，按键可以正常关/开背光，亮度保持 77、音量保持 65。
- 退出后，新拷入中文文件名音乐可播放，PNG 可显示。音乐→语音→音乐恢复后，PA 输出和引脚为 1，DAC 回采非零；一次恢复测量 mean_abs=10096/230/109。该测量验证硬件音频链路，不等同于人工评价音质。
- USB 退出后语音会话、时间工具和 StepSearch HTTPS 查询完成。当天新闻未找到匹配日期的来源时回复“今天没有查到新新闻”；最近科技新闻查询返回两条短摘要，无网址播报，response=completed。测试使用串口文本注入真实会话，不等于真人麦克风 ASR 或声学打断复测。
- 原生 USB 烧录与独立 CH340 烧录均成功且校验通过。未写 eFuse、未擦 NVS、未格式化 SD；测试文件清除后，SD 根目录恢复原来的 5 项。

## 资源与证据

应用 Flash 使用约 3.70 MiB，占 10 MiB 应用分区约 37%；静态片内 RAM 72,180 字节。普通模式约 61–62 KB 内部堆，USB 模式约 57 KB；USB 任务随退出释放，任务数从 25 回到 24。语音活动期间内部堆约 14–21 KB，仍须谨慎增加与语音并行的片内内存负担。

[截图索引](../validation/1.1.0/index.html)、主机测试结果和脱敏硬件检查摘录保存在 `validation/1.1.0/`。完整诊断、临时测试素材与 SD 原文件备份放在项目外归档，不进入发布包。

## 未覆盖的边界

Windows/macOS 实机、独立充电器/纯充电线物理试验、不同容量及文件系统的 SD 卡、写入中断电故障注入和电脑休眠恢复尚未实测。固件将 USB suspend 视为暂停而非拔线，继续保持 SD 独占；未使用超时强制退出已连接的电脑。标准 MSC 不需要额外存储驱动，但不能据此宣称已完成所有系统兼容性测试。
