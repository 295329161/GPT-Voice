# 桌面终端架构

首版采用 ESP-IDF 5.5 / LVGL 8.3，硬件驱动延续已验证的四通道 TDM、ES8311 32-bit slot 修复和 RGB565 字节交换。摄像头仍断电。

## 模块边界

- `core/terminal`：配置 NVS、状态锁、有界后台操作队列。UI 读取快照，所有慢操作通过作业队列提交。
- `core/resampler`：24/16 kHz 双向流式 FIR 重采样；保留跨块历史，避免音频块边界断裂。
- `core/path`：SD 根目录边界和 FAT 文件名校验。
- `core/usb_disk`：USB 扇区读写边界检查、跨扇区部分写保留相邻数据，以及可回绕的 60 秒初始连接计时。
- `core/conversation`：按用户 item ID 与回答 response ID 保存最近 8 轮对话，用户转写与助手流式文字分别更新，再按“你／助手”顺序呈现；避免异步事件到达顺序颠倒角色。
- `services/network`：Wi-Fi、SNTP、天气、短期开启的网页配置和信息查询。Open-Meteo 查询无需密钥；Tavily 为可选备用搜索供应商。
- `services/storage`：挂载、目录快照、文件操作；有占用的音乐文件禁止修改。不格式化用户 SD 卡，不覆盖已有改名目标。
- `services/usb_transfer`：TinyUSB 0.19.0~3 MSC 与 SD 独占交接。先停止语音/音乐、卸载本机 FAT VFS，再开启原始 SD 扇区访问；弹出响应发送完毕后停止 USB，释放 SD host 并重新挂载。USB 任务及 DMA 暂存仅在传输时分配，固定协议缓冲为 512 字节。中断分配和释放均在核 0。释放 SD 时使用实际槽位的 deinit，避免全局 deinit 误复位未使用槽位中的 GPIO0。
- `apps/usb_transfer_view`：原创 LVGL USB 图标、深色状态卡、传输计数和开启前确认。确认框随页面销毁；取消不启动后台切换。读写失败保留电脑独占并显示提示，不擅自挂载本机文件系统。
- `services/media`：MP3/WAV 文件流解码、播放状态、音频采样率管理；语音抢占时暂停，返回后手动恢复。
- `services/tools`：语音工具注册表、参数校验与执行分发；注册 `get_time`、`get_weather`、`web_search` 和 `external_web_search`（仅在提供 Tavily Key 后向模型公布）；无参数工具将 parameter 设为 NULL。时间工具读取 SNTP 校准时钟，未校时返回错误。
- `services/voice`：StepAudio WebSocket 事件与分片、会话配置、AEC、采集、播放、工具任务。Step Plan 会话通过 `services/step_search` 调用官方搜索 MCP，明确查询在本机转写后派发；检索完成后才触发回答，其他端点保留原生搜索。所有队列和网络消息均有上限。
- `services/bluetooth`：BLE 扫描、GATT 客户端连接、加密配对和绑定。具体 GATT 服务留待后续。
- `services/sensors`：100 Hz 目标姿态采样和平滑；游戏负责相对中立位置校准。
- `apps/shell`：应用注册表、返回历史、深色主题、配置与文件页面。
- `apps/games`：雷电突击、层叠三消、Color Flood 的 LVGL 视图；离开页面停止更新。`core/arcade` 独立实现射击与三消规则，固定容量对象池，可在主机上验证。`assets/ui_art` 由 `scripts/generate_ui_art.py` 生成原创抗锯齿图案，采用面板要求的交换字节 RGB565+A。`apps/weather_view` 实现动态天气场景；主页／菜单禁用滚动并向根页面传递手势。

## 添加应用

1. 在 `apps/` 增加独立页面实现，使用统一按钮和标签创建工具，内容节点从 `shell_content()` 获取。
2. 定义静态 `terminal_app_t` 描述符，登记 ID（自定义应用使用 100 以上）、名称、图标、颜色、创建／进入／离开／销毁回调；调用 `shell_register_app()` 并加入 CMake。菜单自动按每页四项分页。
3. 新的慢操作应定义服务接口和作业类型，由后台执行；不要在 LVGL 回调执行联网、长时间解码或持久写入。
4. 页面离开时释放自己拥有的对象／定时器；音乐是共享后台服务，语音则必须停止采集。语音文字仅在变化时刷新，默认跟随底部；手动拖动时暂停跟随，返回底部或点击“最新”恢复。
5. 新的服务器接入放到独立服务适配器。界面与语音工具共用同一业务能力，不各实现一份网络协议。

## 实时音频

硬件保持 16 kHz、两个 32-bit I2S slot。ES7210 缓冲为四路 16-bit 数据：slot0 是 DAC 回采，slot1/3 是麦克风。首版取 slot1 和 slot0 做 ESP-SR AEC（VOIP 低开销模式，处理后限幅放大 4 倍），转换为 24 kHz 单声道 PCM16 后进入独立上传队列。采集任务固定在核心 1，上传任务合并最多 4 帧发送，避免网络等待导致采集丢帧。两者通过连接代次和互斥锁处理退出与重新连接。上传队列短时满时淘汰最旧帧、保留最新语音，继续采集，避免一次拥塞永久关闭聆听。服务返回 24 kHz PCM16，低通重采样为 16 kHz，再复制到立体声并写入 32-bit slot 高 16 位。

语音活动由 StepAudio server_vad 判断，能量阈值为 300。语音期间暂时关闭 Wi-Fi 省电，退出恢复原值。WebSocket 收发使用独立锁。WebSocket 接收线程检测新语音时立即静音、递增播放代次并丢弃旧缓冲；事件任务再取消在途回答。JSON 消息携带接收时的代次，避免积压的旧回答事件重新启动旧音频。离开页面立即禁止继续采集／上传，再由后台安全销毁连接与 AEC。板上回采参考是否具有适合 AEC 的幅度和延迟，必须用真实扬声器音量与说话场景调试。

## 播放器依赖

`apps/music_view` 独立渲染 320×240 横屏播放器：浅色渐变、默认音乐封面、去扩展名的滚动歌名、播放／暂停、前后曲和音量。按钮复用后台音乐作业，音量在松手后走原配置保存流程。服务根据播放状态回调记录单调时钟，暂停累计、恢复续计，换曲重新计时；没有解析总时长或提供拖动定位，界面只显示实际已播放时间。默认封面由 LVGL 图形组成，不冒充文件内嵌专辑图。

音乐状态进入 PLAYING 时显式打开功放，暂停／停止时关闭；语音占用期间由 Voice 控制功放。恢复音乐先检查采样率重设是否成功，再请求续播。不能只根据解码器 PLAYING 状态断定扬声器已出声：Voice 退出会关闭 PA_EN，而上游播放器从暂停恢复不会再次调用文件开始时的 unmute。串口 `audio-probe` 在非语音占用时通过服务任务读取功放输出与引脚电平，再对 DAC 回采和两个物理麦克风做短时幅度统计，不保存或输出录音。

全局提示带独立的更新序号，界面仅在新提示产生时显示 4.5 秒，换页时隐藏历史提示。SD 列表扫描成功不产生计数提示，目录截断和操作错误仍可见。导航仅隐藏进入前的旧提示，刚提交操作产生的新结果继续显示。目录读取区分 EOF 与 I/O 错误，检查非法/重复条目及 stat 失败；失败不覆盖上一次有效快照，提示安全卸载并重新挂载。SDMMC 单线总线限 10 MHz。

`components/audio_player` 保留上游 1.0.7 的 Apache-2.0 许可，并修复 ID3 元数据跳过、无效帧头导致的死循环、跨缓冲同步字与输出错误处理。Helix 解码器仍通过组件管理器获取。构建脚本会监测所有组件的 CMake、Kconfig 和清单变化，避免链接旧缓存。

## 资源与限制

`services/backlight` 将 GPIO0 配置为上拉输入，在独立的核心 0 任务中每 10 ms 采样，`core/button` 对按下和松开均做 30 ms 消抖，每次稳定按下仅切换一次，启动时须先稳定松开才接受按下。只改变 GPIO42 的 LEDC 背光占空比，不暂停 LCD、触摸、音频或网络，也不进入系统休眠。背光开关状态只在 RAM 中，初始化固定开启；设置更新通过同一互斥入口刷新有效亮度，避免熄屏时调节音量／亮度把背光重新点亮。恢复使用配置中保存的亮度，BOOT 的上电启动选择作用和硬件复位线路保持原样。

- LVGL 对象、样式及绘制临时内存通过 `core/lvgl_memory.h` 分配到 PSRAM，避免挤占 Wi-Fi 与 TLS AES DMA 所需的片内连续内存；LCD 传输缓冲仍由 esp_lvgl_port 独立按 DMA 能力分配。
- 文件列表上限 96 项；音乐索引上限 96 首，递归深度 8。
- 图片上限 1 MiB 文件、1,048,576 像素面积且单边不超过 2047；仅基线 JPEG/PNG，不含渐进式 JPEG；超限明确提示。图片解码仍由 LVGL 按需执行，大图切换耗时需实测。
- WebSocket 单消息最多 64 KB，接收队列最多 64 条消息；上传队列 32 帧；播放队列 1024 个最多 256 样本的块（容量上限 16.4 秒，实际按分块大小约 12 秒），溢出取消本轮。缓冲使用 PSRAM，并在打断时立即清空。
- 中文字体包含基本 CJK 区，可显示绝大多数常用汉字；扩展区生僻字不保证覆盖。
- 配置网页由屏幕开启，10 分钟后关闭，提交须携带屏幕配对码。密钥留空保留原值，不提供完整密钥读取接口。
- 预览模型、WebSocket 工具形状和第三方服务行为仍需持有效密钥实测。没有结果时返回错误，不能声称完成查询。

## 硬件测试基线

旧硬件演示及私有 Flash 备份已移至项目外的“项目归档”，不属于发布源码。当前分区将应用扩大为 10 MB，以容纳字体、BLE、TLS 和 AEC。没有 OTA 分区。

语音接收使用 `core/ws_text` 按 WebSocket FIN 与 continuation 合并消息，并检查每帧偏移和累计长度；控制帧不会打断组包。消息同时带连接代次与播放代次，重连后的旧事件不会写入新会话。服务 worker 定期检查回答进度，并在应用事件空闲时发送空 session.update 探测；发送失败、连接断开、探测超时、回答无进展或接收损坏会触发最多两次重连。发送失败与断开立即标记恢复请求，不再等待会话就绪超时。自动重连保留本地历史显示，不会自动重发用户问题或恢复远端上下文。

顶栏 Wi-Fi 图标由 shell 统一创建与更新，weather_view 不再单独管理连接图标。games_create 接收独立的工具栏父对象，游戏画布与工具栏分开布局。core/tilt 提供时间相关的低延迟滤波、角度环绕及带死区的速度映射；sensors 通过固定周期调度读数，避免 I2C 耗时累加到采样周期。

## Step Plan 搜索完成路径

`core/search_intent` 区分查询、取消和已有结果追问，提取检索关键词并为今日查询补齐设备日期。`services/step_search` 在工具任务中使用原有阶跃凭据访问固定 HTTPS MCP 端点，执行 initialize、initialized 和 web_search，验证证书且不跟随重定向。总请求预算 25 秒，单次 HTTP 超时最多 12 秒，接收上限 128 KiB。`core/search_evidence` 校验 JSON-RPC 请求 ID，读取 MCP 文本中的结构化结果，最多保留 5 个来源，分别限制标题、日期、摘要和 3200 字节正文摘录，保留展开追问所需事实，避免整页正文和 MCP 重复字段挤占上下文。

真实语音仍使用服务端 VAD。收到当前轮的搜索转写后，取消尚未基于资料的回答，停止旧音频，再异步检索。工具任务等待原回答结束后写回资料并启动后续回答；打断或退出导致代次失效，旧结果不再写入会话。迟到的旧轮转写只回填显示，不触发新的搜索。当前时间／日期明确问句由同一流程直接派发 `get_time`。普通对话、原有天气函数、分帧接收和有界重连继续保留。音频采集每 16 帧让出一个调度 tick，避免连续 AEC 处理饿死核 1 的 idle 任务。

串口 `voice-test <文本>` 使用正在运行的真实会话进行文本输入、检索与语音回答诊断，仅显式测试记录结果正文；不会输出凭据，也不将日常语音转写新增到日志。

新闻查询从真实记录生成包含事实摘要和正文摘录的会话资料，今日请求只保留日期匹配的来源。会话提示要求默认两三句、60 个汉字以内；新闻先合并重复事件、只讲两条重点，追问也保持简短，明确要求详细解释才展开。该长度由模型归纳遵循，不通过切断播放或截断句子实现。用户按主题或序号追问时根据已有资料回答，不重新搜索追问句。资料里的 URL 字段及摘要／正文内嵌网址全部移出语音上下文，完整来源存入独立的 8 KiB 状态缓冲，由 GPT Voice 的“来源／对话”按钮切换查看。正常对话滚动和来源查看各自处理，不把网址混入语音转写。

AEC 采集任务固定在核心 1；消息解码、工具、上传和播放任务固定在核心 0，避免消息解码占满 AEC 让出的时间片而使核心 1 的空闲任务饥饿。保留看门狗、有界队列和现有恢复逻辑。

## 1.0.0 审查后的约束

配置更新使用 `terminal_config_update`，以字段组为单位合并到最新配置，再由独立互斥锁保护 NVS 写入；网络慢请求不能用旧快照覆盖音量、亮度或 API 字段。相同内容不反复写 Flash。Wi-Fi 页面重连当前网络时允许空输入保留已存密码。

WAV 仅接受 PCM16、1/2 声道、8–48 kHz；RIFF、chunk、fmt、字节率、对齐与 data 长度均经过验证，元数据按偶数字节对齐，读取不越过 data 末尾。暂停后的 STOP 明确转为 IDLE 并释放文件。HTTP 响应溢出必须整体拒绝，禁止跨地址自动重定向。

BLE 新连接在旧连接关闭回调后启动；只处理匹配当前连接地址/ID 的断开事件，只为当前选中的 peer 接受安全请求。没有实现 GATT 业务或数字确认输入。

串口诊断是物理接入接口，没有开放网络调试控制。`services/diagnostics` 只生成与清除独立的测试目录，拒绝覆盖已存在目录，清除前验证标记，仅删除固定测试文件。LVGL 输入注入在锁内注册独立指针设备，触发真实页面事件；其验证不等于人工操作物理触摸面板。

图片先通过 `core/image_info` 校验 PNG IHDR 或基线 JPEG SOF 尺寸，限制文件/像素/单边长度，再从有界 PSRAM 缓冲解码。避免 LVGL 标准文件驱动的 256 字节路径限制和大小写/.jpeg 扩展名匹配问题；离开页面后先销毁对象、失效图片缓存，再释放编码缓冲。
